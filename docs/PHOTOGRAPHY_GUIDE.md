# 摄影集：Markdown 模块写法

照片用 Markdown 图片语法，文字照常写；特殊排版用 `::: 模块名` 开始、单独一行 `:::` 结束。模块名使用中文，不区分横图、竖图和方图，网站按真实比例自动适配。

**启用条件：仓库 Settings → Pages → Build and deployment → Source 选择 GitHub Actions。** 本次新增的 `Build and deploy OPTICS` 工作流负责自动转换和发布。切换后到 Actions 手动运行一次该工作流；以后照常上传照片和 `.md` 即可。若 Source 仍为 Deploy from a branch，旧 YAML 继续发布，新写法尚未启用。

- [可直接复制的摄影集范本](../_examples/photography-template.md)
- [全部模块的可复制示例](../_examples/photography-modules.md)
- [旧 YAML 写法](PHOTOGRAPHY_YAML_GUIDE.md)：原文件继续可用，不需要立即迁移。

## 最短的完整摄影集

```markdown
---
title: 摄影集示例
date: 2026-09-07
location: 示例地点
image_base: /assets/images/my-album/
cover: 01.jpg
cover_theme: light
---

![图片说明](01.jpg)
图注：这是一段图片说明示例文字。

这是一段示例文字。

::: 双联
![](02.jpg)
![](03.jpg)
组注：这是一段图片说明示例文字。
:::
```

开头 `---` 之间仍是整篇信息；照片和正文写在第二个 `---` 后面。**新写法不再填写 `blocks:`，也不需要 `photography_style`。** 标题、日期、地点、简介、设备、封面等现有字段保持原有含义。

`image_base` 统一指定照片目录，下面只写文件名。以 `/` 开头的站内路径、`https://` 或 `http://` 完整地址照常使用，不加目录前缀。文件名大小写、扩展名必须与上传的照片一致。带空格的文件名可写为 `![](<照片 01.jpg>)`。

开场照片直接作为正文的第一张图片即可，第一组也可以是双联或其他模块。旧的 `opening` 字段仍兼容，但新文件无需额外填写。

## 列表封面的深浅与地点

影像列表默认采用居中刊头的杂志封面：桌面三列，较窄屏幕两列，手机一列。右上角可以切换成列表，列表缩略图为纯图片，没有深浅颜色外框。封面照片、标题、日期和地点都从本篇的开头信息自动读取。

```yaml
cover: 01.jpg
cover_theme: dark
location: 苏州
```

- `cover_theme: light`：浅色封面，也是未填写或填写其他值时的默认值。
- `cover_theme: dark`：深色封面。不按摄影集顺序自动换色，每一期单独设置。
- 封面从上到下依次为：居中 OPTICS、中文标题、细分割线、日期与地点、照片。`location` 与日期一起居中显示在分割线下方，地点为空时不显示。
- `cover` 继续支持 `image_base` 加文件名。封面照片统一显示为 **3:2 横幅**，其他比例按中心裁切填满；只改变封面显示，不改动原始图片，摄影集内页仍显示完整照片。

旧 YAML 摄影集也能使用相同字段。此设置控制影像列表和首页的摄影集封面，不影响摄影集内页。首页会自动展示日期最新的三个摄影集，无需填写 `featured`。

## 全部版式对应表

A/B/C 等编号只用于对应视觉参考，实际写作不需要填写编号。以下每个特殊模块最后都要用 `:::` 结束。

| 视觉参考 | 版式 | 开始标记 / 写法 |
| --- | --- | --- |
| M01-A / B / C | 横 / 竖 / 方单图 | 直接写 `![](照片名)`，或使用 `::: 单图` |
| M02-A / B / C | 横横 / 竖竖 / 方方双联 | `::: 双联`，内部两张照片 |
| M02-D / E | 竖横 / 横竖双联 | `::: 双联`，按左到右排列文件名 |
| M03-A / B / C | 三竖 / 三横 / 三方 | `::: 三联`，内部三张照片；混合比例也支持 |
| M04-A / B / C / D / E | 各种横竖方组合，左大右小 | `::: 左大右小` |
| M04-F及其他镜像 | 右侧为主图 | `::: 左小右大` |
| M05-A / B / C | 横 / 竖 / 方图配短文，文字在右 | `::: 短图文` 或 `::: 短图文 右文` |
| M05的左右镜像 | 短文在左，照片在右 | `::: 短图文 左文` |
| M06-A / B / C | 横 / 竖 / 方图配长文，文字在右 | `::: 长图文` 或 `::: 长图文 右文` |
| M06-D及其他镜像 | 长文在左，照片在右 | `::: 长图文 左文` |
| M07-A | 居中窄栏正文 | 直接写普通 Markdown，或 `::: 文字` |
| M07-B | 左半栏正文、右半栏留白 | `::: 左文` |
| M07-C | 左半栏留白、右半栏正文 | `::: 右文` |
| M07-D | 两栏正文 | `::: 双栏文字`，中间用一行 `+++` 分栏 |

**左文 / 右文始终指文字栏的位置，不是文字的对齐方式。** 段落仍沿用文章正文的左对齐规则。短图文的侧边文字垂直居中，长图文顶部对齐；长短由你选择，不按字数自动切换。

方图和竖图的图文模块使用对称两栏；横图的照片栏稍宽。左右换位采用同一比例的镜像，文字块会使用所在栏的可用宽度，最长保留 34em 的阅读宽度。

照片在模块内按文件顺序从左到右排列。两张普通图片即使相邻，也仍是两个单图模块；只有放在双联标记内才组成双联。大小图继续按照片本身垂直居中，图注长短不会带偏照片位置。

## 图注、组注与图片说明

```markdown
::: 双联
![第一张的图片说明](01.jpg "第一张的图片标题")
图注：这是一段第一张照片的图注示例文字。

![第二张的图片说明](02.jpg)
图注：这是一段第二张照片的图注示例文字。

组注：这是一段整组照片共用的图注示例文字。
:::
```

| 写法 | 用途 |
| --- | --- |
| `![图片说明](文件名)` | 方括号为 alt，供读屏与图片加载失败时使用，不是图下文字 |
| `![](文件名 "图片标题")` | 可选的 title，作为图片标题属性；浏览器通常在鼠标悬停时显示 |
| `图注：文字` | 显示在紧邻的上一张照片下面 |
| `组注：文字` | 显示在整个双联或三联下面，只用于这两种模块 |

图注和组注只显示文字，不显示照片编号；页头仍显示整本的照片总数。

三者都可以省略。图注和组注写成一行普通文字，不需要引号或缩进；半角冒号 `图注:`、`组注:` 也能识别。它们使用现有图注样式，暂不解析加粗等 Markdown 标记。

图注紧跟对应照片，允许中间空行，但不要插入正文。大小图、长短图文内也按同样方法填写每张照片的图注。图文模块内**没有“图注：”前缀的文字就是正文**，不会被自动当作图注。

如果正文恰好要以“图注：”开头，写成 `\图注：`。代码块、引用块和列表里的这些文字仍按普通 Markdown 处理。

## 长短图文与文字位置

```markdown
::: 长图文 左文
![](01.jpg)
图注：这是一段图片说明示例文字。

## 示例标题

这是一段示例文字。

这是第二段示例文字，可以使用 **加粗**、*斜体*、[链接](https://example.com)。

> 这是一段引用示例文字。
:::
```

把第一行换成 `::: 短图文 左文` 就使用短图文；换成 `::: 长图文 右文` 则文字在右、图片在左。照片写在模块内部的前面或后面都可以，最终位置由标记决定。每个图文模块恰好包含一张独立图片和非空正文。

标题使用 `## 示例标题`，无需另写 `heading:`；正文不用 `text: |`，也不用缩进。横竖方照片使用相同写法。

## 纯文字与两栏

```markdown
::: 左文
## 示例标题

这是一段示例文字。右半栏留白。
:::

::: 双栏文字
## 左栏示例标题

这是一段左栏示例文字。

+++

## 右栏示例标题

这是一段右栏示例文字。
:::
```

左文换成右文即交换文字栏与留白。双栏文字内部只有一个 `+++`，两边各有正文。普通 Markdown 分隔线 `---` 仍可以写进文字栏；代码块里的 `+++` 不会分栏。模块不嵌套。

## 页面留白与手机排列

留白现在由摄影详情页右上角的两个图标控制：**Full（铺展）为默认，Airy（疏朗）可随时切换**。标题区保持固定，图片大小和模块之间的留白一起改变。每次新打开页面恢复 Full，不修改摄影集文件。

写作时无需填写 `density`，也不需要在模块名后添加 `疏朗` 或 `铺展`。旧文件中的这些设置仍能被解析，但不再影响页面排版，也不会阻止按钮切换；不必批量修改旧摄影集。

```markdown
::: 双联 手机并排
![](02.jpg)
![](03.jpg)
:::

::: 长图文 左文
![](04.jpg)

这是一段示例文字。
:::
```

| 选项 | 适用范围 | 效果 |
| --- | --- | --- |
| `左文` / `右文` | 长图文、短图文 | 指定文字所在的一侧；默认右文 |
| `手机并排` / `手机堆叠` | 双联 | 覆盖手机端的默认排列 |

不同模块之间的纵向间距，桌面为疏朗 224px / 铺展 144px，手机为疏朗 112px / 铺展 80px。双联、三联和大小图内部仍使用各自的图片间距。选项用空格分开，不要求固定顺序。

手机默认规则不变：三联逐张展开；双联中的横横组合上下排列，竖竖、方方及混合比例保留并排；图文和双栏文字改为纵向阅读，留白半栏收起。

极少数需要加载前预留比例的照片，可以在其后写 `比例：3:2`、`比例：2:3` 或 `比例：1:1`。这是可选提示，不强制裁切，照片加载后以真实尺寸为准。

## 怎么上传

1. 确认已经完成本页开头的 GitHub Actions 一次性设置。
2. 照片上传到 `assets/images/你的文件夹/`。
3. 从范本复制 `.md`，填写整篇信息，按页面顺序选择模块和照片。
4. 摄影集上传到 `_photography/`。已在本地使用 Git 时，也可以将照片和 `.md` 一起提交。
5. 等 Actions 中的 **Build and deploy OPTICS** 成功，打开摄影集页面。

新语法写错时，构建日志会指出文件、行号和原因，例如“双联需要 2 张照片，目前有 1 张”。构建未通过时不会发布不完整的新版本。

普通 Markdown 编辑器可以编辑文件，但未必能预览这些专用版式；准确预览需要网站构建环境。`image_base` 也是网站约定，本地编辑器通常不会自动拼接该路径。

## 旧文件与代码逻辑

有 `blocks:` 的旧摄影集继续使用原模板，源文件不会被自动重写。新摄影集没有 blocks，照片和文字写在正文；同一文件不要同时使用两种模块写法。旧 YAML 的写作说明保存在单独指南中。

转换只发生在临时构建目录 `_content_build/`：新 Markdown → 现有 blocks 数据 → 现有 Jekyll 模板。转换结果不回写 main，也不要求你维护第二份 YAML。文章、首页等文件原样进入同一次 Jekyll 构建。

开发者本地预览：

```bash
npm ci --prefix tools/content-build
npm test --prefix tools/content-build
node tools/content-build/cli.mjs prepare --include-examples
bundle exec jekyll serve --source _content_build
```

修改源文件后重新运行 prepare；不要编辑构建目录里的生成文件。只检查语法时运行 `node tools/content-build/cli.mjs check --include-examples`。
