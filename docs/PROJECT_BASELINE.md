## 1. 文件的权威顺序

发生冲突时按以下顺序处理：

1. 用户当前明确提出的要求
2. 根目录 `AGENTS.md`
3. 本文件记录的项目基线
4. 仓库 `main` 分支的最新代码
5. 旧对话中的描述或模型记忆

旧对话和记忆只能帮助定位线索，不能代替原文件、Git 提交或视觉母版。

### 摄影集写法与发布（2026-09-07）

- 中文标记：单图、双联、三联、左大右小、左小右大、短图文、长图文、文字、左文、右文、双栏文字。
- 长短图文可附加左文或右文，始终指文字所在侧；双栏文字用 +++ 分隔。图注紧随照片，组注只用于双联、三联。疏朗/铺展适用于所有模块，手机并排/手机堆叠只用于双联。
- 普通图片不会按数量自动合组，横竖方仍按真实尺寸适配。新语法的任何后续变更必须同步指南、范本、解析和验证，禁止仅改名称导致旧文件失效。
- `tools/album-markup` 只写 `_album_build` 临时副本，原始文章、摄影集和元信息不会被转换程序覆盖。新格式错误会终止构建；旧 YAML 既有错误只提示并保留原文件，不能猜测缺失照片。
- GitHub Pages 已启用 GitHub Actions，手动工作流 34176334532 的构建与部署均成功。`Build and deploy OPTICS` 负责构建和发布；指南保留新仓库的一次性启用步骤。

## 4. 内容所有权与占位规则

### 受保护的真实内容

以下内容默认是用户内容，不得改写、删减或替换：

- `_posts/**` 中的文章正文
- `index.html` 中用户已经修改的首页文字
- `about.md`
- `_includes/footer.html`

真实文章中的图片引用即使失效，也不能擅自用占位图替换；应单独报告问题，等待用户提供或确认图片。

### 占位内容

当前 `_photography/**` 中标题以“摄影集示例”开头的条目属于模板占位内容。

占位文字只允许使用：

- 标题：`摄影集示例 01`
- 说明：`这是一段摄影集的示例文字。`
- 正文：`这是一段摄影集正文的示例文字。`
- 图注：`这是一段图片说明示例文字。`
- 地点：`示例地点`
- 设备：`示例设备`

禁止为占位内容虚构人物、经历、城市观察、情绪或文学化叙述。

### 占位图片

唯一的网页占位图片为：

`/assets/images/window-light.webp`

内容描述：眼镜放在桌面上。所有示例封面和示例摄影集统一引用此文件，不生成新的替代图片。

`city-rain.webp` 与 `night-platform.webp` 为旧占位资产。可以保留文件，但新页面不得继续引用，除非用户明确指定。

## 5. 页面结构

| URL/类型 | 作用 | 不得混淆为 |
|---|---|---|
| `/` | 首页入口 | 文章列表页 |
| `/journal/` | 文章卡片列表 | 文章详情 |
| `/journal/:title/` | 单篇文章详情 | 摄影详情 |
| `/photography/` | 刊物封面网格形式的摄影集列表 | 精选照片墙 |
| `/photography/:name/` | 单个摄影集详情 | 文章卡片 |

有摄影集后，首页不再新增“精选照片”区域。

## 6. 局部修改协议

用户要求“只改某处”时：

1. 先记录目标文件和目标选择器。
2. 保存修改前的提交号与文件 SHA。
3. 只修改目标范围。
4. 对比修改前后差异，确认没有额外文件或额外选择器变化。
5. 若结果不满意，直接恢复该范围的旧代码，不重新设计其他部分。

禁止用整份新文件覆盖用户已经更新的同名文件。

## 7. 版本恢复协议

- “恢复上一版”意味着从 Git 历史恢复，不意味着重新生成相似版本。
- 用户指出某个历史截图时，先定位截图对应提交或资产；定位失败就明确询问。
- 每个已确认的视觉阶段都应保留独立提交号。
- 后续可增加 `docs/reference/`，保存首页、文章列表、文章详情、摄影列表和摄影详情的已确认截图。截图一旦标记为 approved，除非用户要求更新，否则不得替换。
