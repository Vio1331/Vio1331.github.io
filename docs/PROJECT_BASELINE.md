# VIO 网站项目基线

最后核实：2026-09-12。本文只描述当前实现；被后续要求取代的方案从 Git 历史查阅，不再叠加为现行规则。

## 权威顺序与内容保护

1. 用户当前明确要求。
2. 根目录 `AGENTS.md`。
3. 本文记录的当前基线。
4. 远端 `main` 的最新代码。
5. 旧对话与记忆，仅作为定位线索。

修改前核对远端最新提交和文件 SHA，保留用户后续手动修改。恢复旧版本必须从准确的提交或原始资产提取，不凭描述重画。真实文章、摄影集、首页与关于页文案、页脚文案及图片均属于用户内容。失效的真实图片不得换成占位图。

## 色彩、字体与资产

- 界面色板唯一来源是 `assets/css/main.scss` 的 `:root`：纸白 `#f7f3ee`、卡片白 `#fbf8f4`、墨色 `#25211f`、正文灰 `#4a4540`、辅助灰 `#8a8078`、珊瑚橙 `#c96749`，以及 `--paper-deep`、`--rule`。独立 CSS 引用这些变量，透明色由变量派生。
- 标题使用 `LXGW WenKai TC` 700，精确范围以 `assets/css/title-font.css` 为准，包含首页、文章、摄影与关于页已确认的标题。正文及导航继续使用原有无衬线字体；Andika 用于相应英文标签，Freeman 用于 OPTICS 品牌。
- Freeman 请求只包含 `text=OPTICS`，品牌字距为用户当前值。更改品牌文字时需同步子集字符，不随意扩大字体作用范围。
- Logo 来自 `_includes/brand-mark.html` 和 `assets/images/favicon.svg`。照片、头像及旧资产不调色、不重绘；仅凭“当前未引用”不能认定用户素材可以删除。
- 示例只使用中性文字和 `/assets/images/window-light.webp` 眼镜桌面图；不虚构经历、地点故事或摄影叙事。

## 页面职责

| 页面 | 当前行为 |
| --- | --- |
| `/` | 开场、文章、摄影三屏；摄影屏直接接页脚 |
| `/journal/` | 文章列表，默认卡片，可切换细线列表 |
| `/journal/:title/` | 文章详情，固定居中宽版、章节目录、篇末导航 |
| `/photography/` | 摄影集列表，默认杂志封面，可切换缩略图列表 |
| `/photography/:name/` | 摄影详情，文档决定 Full / Airy，无读者版式切换 |
| `/about/` | 关于页和头像悬停效果 |
| `/feed.xml` | 文章 Atom 订阅，页脚入口标记为 RSS |

### 首页与关于页

- 首页按日期倒序，文章与摄影各显示一个主卡和两条次条。文章卡片在左、装饰「文」在右；摄影完整封面在右、用户上传的叠放相片符号在左。
- 摄影主卡独立于摄影列表封面，与首页文章主卡同步宽高；顶部照片裁切填满，底部是标题、简介、年月和入口，不显示地点，不读取 `cover_theme`。次条日期为 `YYYY.MM.DD`。
- 「文」使用已确认的 Noto Sans SC 900 原始 SVG 轮廓；图片符号沿 2026-09-12 上传的 `0b01f520-8a91-4d4c-ae9c-94066c28b5c2.png` 透明轮廓描成 SVG，保留叠放相片、相框、山形与圆形太阳，内部镂空按原图保留。
- 两个装饰静态显示，填充 `var(--card)`、描边墨色 22% / 1px，无描边动画。桌面尺寸为 `clamp(20rem, 44vw, 42rem)`，800px 以下 `18.5rem`；桌面外移 `-0.25em`，窄屏 `-0.23em`。
- 手机首页标题随屏宽缩放，320px 下不产生最后一字孤行；380px 以下摄影主卡标题与日期分行，次条日期允许换行。窄屏导航及卡片／列表切换按钮至少 44px，目录入口至少 44px 高。
- 关于页初始头像是 `/assets/images/about-avatar.svg`；鼠标每次进入圆形头像随机显示 `assets/images/avatar/` 中的图片，离开或失焦恢复原图。候选由构建自动发现，文件名空格原样保留，非图片不参与。

### 列表与标题区

- 两个列表的卡片／列表双按钮共用一个外框，默认卡片，不保存跨页面状态。切换组件只在列表页加载。
- 文章卡片桌面三列，1040px 以下两列、600px 以下一列；保留较小圆角与分类配色。摄影封面桌面三列，800px 以下两列、600px 以下一列。
- 首页与影像列表封面通过构建自动生成 320／640／960／1440px WebP 缩略图，不放大较小原图。使用 `srcset` 和自适应 `sizes`，列表切换同步尺寸提示；原图和内页照片保留。外链、动画或不适用的格式回退到原地址。
- 摄影封面从上到下为居中 OPTICS、中文标题、细线、日期地点、3:2 裁切照片。`cover_theme: dark` 为深色，其他值默认浅色。该主题不影响首页和详情。
- 列表模式无上浮、阴影或主题色图片框，悬停和键盘聚焦均保持 `var(--rule)` 分割线；卡片模式保留现有悬停效果。
- 两类列表的抬头在桌面为左标题、右对齐简介；800px 以下简介左对齐。文章详情抬头为标题、日期地点和底部细线，无背景卡片；手机单栏。摄影 opening 桌面同样左标题、右简介与元信息，底部细线；800px 以下单栏、简介与元信息左对齐。

### 文章正文与阅读导航

- `assets/css/journal.css` 管理文章详情抬头、封面、正文、文末及对应响应式规则。共享 `.journal-content` 的段落、标题、引用、代码、表格、脚注等样式值保持原有基线。
- 文章直属正文固定 `min(100%, 50rem)`，小屏自然收缩。无窄版属性、切换按钮或宽窄状态脚本；摄影文字宽度由其模块自行控制。
- 1040px 以下文章宽表格在自身区域内横向滚动，不撑开整页；800px 以下长链接可换行、列表保留编号缩进、引用块缩小侧边留白。宽屏正文样式不变。
- 全站顶栏 sticky。详情返回入口明确指向所属列表，不调用浏览器历史返回。
- 返回入口在详情标题上方，采用细线箭头加“文字”／“影像”的普通链接。摄影不再预留悬浮工具边距。文章目录入口是无外框的“目录”文字；1320px 以下合入现有顶栏，不新增工具行。
- 目录从正文 h2/h3 自动生成，保留既有锚点，为无 ID 标题生成不冲突的 ID；无标题时隐藏目录入口。每篇默认展开，不改变正文横向位置。
- 目录左边距 `clamp(2rem, 3.5vw, 4rem)`，800px 以下与正文外壳同为 `1.1rem`。文字入口与条目间隔 `.875rem`；条目紧凑、三级标题缩进、当前章节珊瑚色。入口展开时墨色，收起时辅助灰；“目录”右侧有细线下拉箭头，展开时转向上方；目录以 260ms 向下展开、向上收起，减少动态效果时无过渡。
- 1320px 以下目录为浮层；点章节或外侧、按 Esc 可收起。关闭时不参与键盘导航；锚点定位避开顶栏。
- `.reading-region` 约束侧栏文字入口、目录和遮罩的下边界，不能覆盖页脚。返回链接随标题正常滚动；小屏目录入口属于全站顶栏。
- 篇末“完”之后，上一篇／下一篇按各自集合的日期倒序衔接，左／右对齐，使用正文文字和真实标题；600px 以下各占一行，长标题使用整栏宽度。桌面首尾缺失的一侧留空，不循环、不跨集合。

### 摄影版式与模块

- 仅有 magazine 模块结构。摄影文档开头写 `density: airy` 则整篇 Airy；省略或写 `density: full` 则 Full。页面无排版切换按钮。
- 旧模块级 `density` 及中文 `疏朗`／`铺展` 仍兼容解析，但不输出局部覆盖；整篇留白统一由文档开头决定。
- 页头和外层纸张沿用 Full 的宽度；Airy 模块内收、照片通常占模块宽度 80%，图文使用同一尺度，不能越界。
- 支持单图、双联、三联、大小图、短图文、长图文、纯文字、左右文字及双栏文字。照片真实比例自动识别，不裁切、不拉伸；方形单图与方形双联沿用标准模块边缘。
- 横图图文为 1.2:1，竖图和方图等宽；左文／右文严格镜像，文字最多 34em、在自身栏内居中，段落左对齐。短图文垂直居中，长图文顶部对齐。大小图按照片中心对齐，不受图注换行影响。
- 模块间距：桌面 Airy 224px / Full 144px；手机 Airy 112px / Full 80px。图片组内部仍使用各自间距；图注无照片编号。
- 摄影容器 800px 以下三联逐张展开、横横与混合比例双联默认堆叠，竖竖与方方保留并排；`手机并排`／`手机堆叠` 优先于默认规则。大小图按文件顺序上下排列，主图整栏宽、小图 80% 宽居中。图文与双栏文字改为单栏，保留原有先后顺序。

## 写作、构建与维护

- 两类内容均支持 `YYYYMMDD_标题.md`，日期与排序以 `date` 为准。文章目录为 `_journal`，摄影为 `_photography`；不恢复旧 `_posts` 或 article/photo 别名。
- 文章 Markdown 由 Kramdown 渲染，`_plugins` 处理稳定链接、SEO、订阅 ID 和共用图片地址；`image_base` 用于相对图片路径。
- 摄影支持 Markdown 中文模块和旧 YAML blocks。`tools/content-build/cli.mjs prepare` 只转换临时副本，不回写用户源文件。
- `.github/workflows/pages.yml` 使用 Node.js 22、Ruby 3.1 和 `github-pages` 232。先执行 Node 测试与 prepare，再运行插件启用的 Jekyll、Ruby 验证及 Pages 部署。禁止恢复不能执行 `_plugins` 的安全模式构建。
- 封面副本在 `_content_build/assets/images/generated/covers/`，构建后进入 `_site/assets/images/generated/covers/`；网站路径为 `/assets/images/generated/covers/`。文件名为内容哈希加宽度，映射为构建内 `_data/cover_images.json`，不覆盖原图、不回写仓库。
- `_content_build`、`_site`、依赖和缓存不提交。代码职责见 `CODE_MAP.md`；写作指南和范本必须与实际解析器同步。
- 每轮任务一个清晰提交，写入前再次核对远端 SHA；视觉改动检查桌面和移动端，发布后核实 Pages 状态。
- 已知缺图以 `MISSING_IMAGES.md` 和 `tools/content-build/known-missing-images.json` 为准。2026-09-11 核实当前仍缺 12 张，均属于《说一声再见，就是死去一点点》；另一篇的旧缺图引用已补传或改名修复。
